# Clerk authentication (dash-clerk-auth, vendored — not on PyPI).
#
# Installed ALWAYS, gated at runtime: with no CLERK_* keys in the environment
# lib/auth.py registers nothing and the site runs fully public. MUST be
# installed WITH dependency resolution (never --no-deps: dash auto-imports the
# package via its [dash_hooks] entry point, so a broken transitive dep crashes
# every Dash() construction app-wide).
#
# The floors below are the fleet security baseline, not a preference:
# clerk-backend-api 5.x capped cryptography at <47.0.0 — below the fixes for
# GHSA-537c-gmf6-5ccf (48.0.1), PYSEC-2026-3553/3554 (49.0.0) and
# PYSEC-2026-3552 (50.0.0). SDK 7.0.0 allows cryptography <51.0.0, and
# dash-clerk-auth 1.0.1 widened its cap to <8 exactly so applications can
# assert these floors rather than merely permit them.
#
# WHY 1.0.5 AND NOT 1.0.2 — this host shipped 1.0.2 on 2026-08-22 and every
# release since fixes something that was live here:
#   1.0.3  Sign Out finally revokes the SERVER session on the click paths.
#          1.0.2's logout is client-side only: it runs Clerk.signOut() and
#          reloads, while the server keeps trusting the signed __dca_identity
#          cookie for the rest of session_lifetime_days (default 7 DAYS). A
#          signed-out browser kept rendering every auth-gated page. With Clerk
#          switched ON here via env group C, that hole was live on this host.
#   1.0.4  FastAPI auth endpoints are CALLABLE for the first time — 1.0.3 (and
#          the line before it) registered them with an un-annotated request
#          param, which FastAPI reads as a required QUERY field: every POST
#          422s. Inert on Flask, fatal here — this service runs
#          DASH_BACKEND=fastapi, and POST /api/auth/session and POST
#          /api/auth/signout were both measured returning
#          422 {"detail":[{"loc":["query","request"],"msg":"Field required"}]}
#          against the live host on 2026-08-22, before this bump. Also the
#          ghost-cookie fresh-load reconciliation.
#   1.0.5  The return-trip stale gate: sign in from a satellite, come back to
#          the page you started on, and the first server render happens before
#          __dca_identity is minted, so the gate card persists until a manual
#          refresh. 1.0.5 syncs the session and reloads once, behind a
#          sessionStorage no-loop marker shared by BOTH reconciliations.
#
# PROVENANCE — the dist/ tarball IS the release; there is no PyPI:
#   sha256  a2f9062e15a69fc79deeaf76fcf1380907a961978db558b2aa227572cb2b74f3
# GENERAL RULE, twice-proven upstream (1.0.4's 22117b20…, 1.0.5's first
# build): early builds go stale on sdist-shipped doc edits and are NOT
# distinguishable by name, size or date — ONLY the recorded sha admits a
# tarball into this file. Vendor from Dash-Clerk-Auth-Hook's dist/ and verify
# the sha before every copy.
# ---------------------------------------------------------------------------

# ---------------------------------------------------------------------------
# AI/LLM integration & SEO — from PyPI (the vendored 2.0.0 sdist is retired).
#
# 2.7.1 is the network floor (the round-3 fleet number). Each step below it
# loses something this site publishes, so the floor is load-bearing for
# HONESTY, not crash avoidance:
#   < 2.7.1  the llms.txt v2 discovery relations go missing — rel=alternate /
#            rel=describedby on BOTH lanes plus the matching Link headers —
#            along with the `Accept: text/plain` ramp and the representation
#            content digest. These are the surfaces the network's agent lane
#            composes over: without them an agent that finds a page has no
#            machine-readable route to that page's prose.
#   < 2.7.0  every page serves a DUPLICATE H1 to crawlers (the injected
#            prerender header plus the doc body's own markdown H1), the home
#            footer prints its /llms.txt link twice, and — the sharp one — a
#            page that merely MENTIONS the prerender marker loses its
#            prerender entirely, because the injector's idempotency probe is
#            a substring match. Two hosts in this fleet blanked their hub
#            pages that way. tests/test_pages.py pins the single-H1 shape.
#   < 2.6.1  the universal prerender ships with a literal `hidden` attribute,
#            so every visibility-respecting consumer (html-to-text extractors,
#            arguably crawler content-weighting) reads "Loading..." where the
#            page's prose should be. The outside-audit finding of 2026-08-22;
#            tests/test_pages.py pins the visible shape.
#   < 2.6.0  the sitemap goes back to lying: `register_page_metadata(lastmod=)`
#            is swallowed into **kwargs and SILENTLY ignored, so every real
#            date this repo stamps reverts to an invented build date. Also
#            loses icon autodiscovery and the JSON-LD publisher logo.
#   < 2.5.1  the Tier-B SEO standard unwinds: no `configure_seo`, the crawler
#            <title> drops to the bare page name, per-page title/image_url
#            never reach the crawler document, /favicon.ico serves the app
#            shell instead of an icon.
# run.py asserts this floor at boot (LLMS_PKG_FLOOR) so a stale environment
# gets a diagnosis instead of a mystery. Both backend extras: prod runs
# fastapi (render.yaml), CI and local dev also run flask.
#
# REMEMBER THE CACHE TRAP (the round-2 fleet lesson, restated here beside the
# number): THIS LINE CHANGING IS THE DOCKER CACHE BUST. The image's pip layer
# re-runs only when requirements.txt or vendor/ bytes change, so a `>=` floor
# can never pull a newer release through a cache hit — an upgrade that isn't
# a floor bump silently keeps whatever version the image was first built
# with. Grep the NUMBER, not the file: it also lives in run.py's boot floor
# and in both ci.yml gates.
# ---------------------------------------------------------------------------
